# 仕組み

## なぜこの形にしたか

旧サイトは、ThemeForest で購入したテーマ（約 4,700 行の XML）に CSS・JS・HTML がすべて入っていた。
直すには Blogger の画面で XML を直接書き換えるしかなく、**保存した瞬間に本番が変わり、差分も履歴も残らない**。

そこで、見た目と動きを GitHub に出した。

- **URL は変わらない**（Blogger がページを返し続ける）
- **コメント・検索・人気記事・ページ送りは Blogger の機能のまま**
- 見た目の変更は Pull Request で確認でき、版番号で本番を固定・巻き戻しできる

別サイトに分ける方式（ヘッドレス）は採らなかった。URL が変わり、コメントや人気記事を作り直すことになるため。

## 誰が何を組むか

| ページ | HTML を組むもの | データの出どころ |
|---|---|---|
| トップ（特集・新着・ラベル別） | `app.js` | 公開フィード `/feeds/posts/summary`（ページを開くたびに取得） |
| 記事・固定ページ | Blogger（`theme.xml` の `Blog1`） | Blogger |
| ラベル別一覧・検索結果 | Blogger（`theme.xml` の `Blog1`） | Blogger |
| 人気記事・ラベル一覧 | Blogger（`PopularPosts1` `Label2`） | Blogger（閲覧数は Blogger しか持っていない） |
| コメント | Blogger 標準 | Blogger |
| ヘッダー・フッター | `app.js`（`CONFIG.nav` `CONFIG.footer`） | — |
| 共有ボタン | `app.js`（`data-share` の箱に入れる） | — |

ヘッダーとフッターを `app.js` に置いたのは、メニューの変更を **XML を触らずに Pull Request だけで** できるようにするため。

## ページの種類の見分け方

`theme.xml` が `<body data-page="…">` に書く。

| 値 | ページ |
|---|---|
| `index` | トップ |
| `article` | 記事 |
| `page` | 固定ページ |
| `list` | ラベル別一覧・検索結果・月別 |

## 公開フィードについて

- `https://ton-press.blogspot.com/feeds/posts/summary?alt=json` で、ログインなしに記事の一覧が JSON で取れる
- ラベルで絞る：`/feeds/posts/summary/-/<ラベル>?alt=json`
- 1 回に取れるのは **150 件まで**（それ以上は `start-index` で送る）
- サムネイルは 72px の正方形の住所で来るので、`app.js` が大きい版の住所に書き換えている
- 画像そのものはダウンロードしない。Google の住所を `<img>` に入れるだけ
- 他のサイトから `fetch` することは許可されていない（CORS ヘッダーが無い）。同じ `blogspot.com` の中からは読める

## 版番号（タグ）

- jsDelivr は `@v0.1.0` のように **タグを指定すると、その時点の中身を固定で** 配る
- `@main` のようにブランチを指定すると、最新の中身が配られる。反映に最大 12 時間ほどかかり、
  **本番に出すと決める前に本番の見た目が変わることがある**ので、本番では使わない
- 番号の付け方：見た目の小さな修正は 3 桁目（v0.1.0 → v0.1.1）、ページ構成の変更は 2 桁目（→ v0.2.0）

## 分かっている限界

- `theme.xml` を Blogger に自動で書き込む手段は無い（API が無い）。殻を変えるときは画面で貼る
- トップの記事は JavaScript で組むので、検索エンジンにはトップの記事一覧が見えにくい。
  記事ページと一覧は Blogger が組むので影響しない
- jsDelivr が止まると見た目が崩れる。`theme.xml` の `<b:skin>` に最低限の読める見た目を残してある
