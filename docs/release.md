# 本番に出す・戻す

**本番の HP は何千人も見ている。** この手順を飛ばさないこと。

## 出し方

### 1. 変更をマージする

1. ブランチを切って直す
2. Pull Request を出す（テンプレートの確認項目を埋める）
3. 別の人に見てもらい、承認されたらマージ

この時点では、本番も試験用ブログも変わらない。

### 2. 版（タグ）を打つ

GitHub の「Releases → Draft a new release」で、`main` に新しいタグを付ける。

- 例：`v0.1.1`
- 説明欄に、何を変えたかを 1〜3 行で書く

### 3. 試験用ブログで確かめる

1. 試験用ブログの Blogger 管理画面 → **テーマ** → 「カスタマイズ」の横の ▼ → **HTML を編集**
2. `@v` で検索し、**2 か所**（`site.css` と `app.js`）の版番号を新しいものに書き換える
3. 保存して、試験用ブログを開いて確かめる
   - トップ・記事・ラベル一覧・検索・固定ページ・PDF版
   - スマホ（実機）
   - 何も変わらないときは、ブラウザの再読み込み（Ctrl+Shift+R）。jsDelivr は新しいタグを数分で配る

### 4. 本番に出す

1. **本番の Blogger 管理画面 → テーマ → ▼ → バックアップ** で、今のテーマを保存しておく
2. 「HTML を編集」で、3. と同じ 2 か所の版番号を書き換えて保存
3. https://ton-press.blogspot.com/ を開いて確かめる
4. どの版を本番に出したかを、Pull Request か Release にコメントで残す

## 戻し方

おかしいと気づいたら、**原因を探す前にまず戻す。**

1. 本番の「HTML を編集」で、2 か所の版番号を **1 つ前の版** に書き換えて保存
2. 直ったことを確かめる
3. 原因は落ち着いてから Pull Request で直す

殻（`theme.xml`）ごと壊れたときは、「テーマ → ▼ → 復元」で、4-1 で保存したバックアップを入れ直す。

## 殻（theme.xml）そのものを変えるとき

版番号の書き換え以外で殻を変えるのは、ページの箱の構造を変えるときだけ。

1. Pull Request で `theme/theme.xml` を直してマージ
2. 試験用ブログに **全文を貼り替え**て確かめる（「HTML を編集」で全選択 → 貼り付け → 保存）
3. 本番もバックアップを取ってから全文を貼り替え
4. 貼り替えると、管理画面で付け直したウィジェットの設定（人気記事の件数など）が戻ることがある。確かめる

## 初めて本番に入れるとき（v0.1.0）

旧テーマから新テーマへの切り替えは、この 1 回だけ大きな作業になる。

1. 本番テーマのバックアップ（2026-10-07 分は 報道部 フォルダに保存済み。直前にもう一度取る）
2. 試験用ブログで、`theme.xml` の全文で問題が無いことを確認済みであること
3. 部会で切り替える日時を決め、アクセスの少ない時間に行う
4. 本番に全文を貼り替え → 確認 → 問題があれば即バックアップを復元
